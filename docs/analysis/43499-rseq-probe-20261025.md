# `disable_rseq_for_thread` 判据与裁撤（2026-10-25）

> 状态：**已裁撤**。`gl43499/core` 内函数定义、声明与 4 个调用点全部删除；
> `very_legacy/` 只读参照不动。本件是该决定的唯一证据记录。

## 1. 结论

| 事实 | 证据 |
|---|---|
| 函数从未有实现 | 本仓 39 个含定义的 commit（`0f7b8676`…`df73c76e`）body 全部 `return;`；上游 PoC `NebuSec/CyberMeowfia` 最早可得树 `8d22bdbaae:src/util.c:143` 亦为 `return;`，且该文件无其它 rseq 代码 |
| 本机不支持 rseq | A301SO 5.15.189-android13-8-00016-g51bba4309aac-ab14546557：`/proc/config.gz` → `# CONFIG_RSEQ is not set` |
| 连注册都不可能 | `rseq(293)` 在主线程 + 3 个 pthread 全部 `ENOSYS`；`auxv AT_RSEQ_FEATURE_SIZE/AT_RSEQ_ALIGN = 0` |
| 不是编号/过滤器问题 | 对照组 `membarrier(283)` 同表可用（ret=127）；探针 `Seccomp: 0`、`NoNewPrivs: 0` |

⇒ 该函数在本设备上**不存在可观测对象**：即使写成真实实现也只会返回 `ENOSYS`。
名字表达的是意图（让当前线程注销 rseq 注册，避免 `rseq_ip_fixup()` 在
`FUTEX_WAIT_REQUEUE_PI` 返回路径上重写 PC / 重放 syscall，从而打断
"waiter 内核栈帧存活到 consumer 走 PI 链"的窗口），但意图从未落地。

## 3. 处置

| 位置 | 动作 |
|---|---|
| `core/support.cpp` | 删函数定义 |
| `core/support.h` | 删声明 |
| `core/race.cpp` | 删 waiter/owner/consumer 三处调用 |
| `core/route_tcp.cpp` | 删 `tcp_punch_thread` 一处调用 |
| `core/` 其它 | `grep -rn disable_rseq_for_thread` = 0 |

**后续形态**：若某 profile 的内核 `CONFIG_RSEQ=y`，不得恢复空壳，而应由 profile 给能力位
（如 `rseq_unregister: bool`），native 侧按位真调
`rseq(area, 32, RSEQ_FLAG_UNREGISTER, sig)` 并检查返回值；未启用时 C 侧不出现该调用点。
注意注销必须传 libc 注册时用的同一 `area` 指针，这是它难以可靠实现的根因。
