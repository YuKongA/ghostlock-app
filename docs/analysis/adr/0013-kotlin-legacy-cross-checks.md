# ADR-0013：Kotlin 侧为旧架构，跨端对拍降级

- 状态：**Accepted**（**用户裁定** 2026-10-09）
- 日期：2026-10-09
- 沿革：用户原话「先不用管 kotlin 对拍，你被 kotlin 旧架构限制了，以后要重写的」

## 1 裁定

1. **跨端对拍降级** ✓：Kotlin（App / profile-core）与 native 之间的**产物对拍**（manifest 逐字节比对、fixture 重冻、双侧枚举一致性测试）**不再是本阶段的推进条件** ✓；
2. **native 侧设计不受 Kotlin 现状约束** ✓：凡「因为 Kotlin 现在是这样所以要这样」的让步 ✗ **一律撤回或改写** ✓；设计按自身正确性推进 ✓；
3. **Kotlin 侧为旧架构，后续重写** ✓ ⇒ 其现有形态**不是**接口的参照物 ✓。

## 2 保留的（不是全部解除）

| 保留 | 为什么 |
|---|---|
| **树内的结构规矩**（如 `queue-removed` ✓：队列键出现即拒 ✓） | 那是 **native 侧**的裁定（`profile/run_plan.hpp`）✓ —— 与 Kotlin 无关 ✓，继续进行 ✓ |
| **native 侧的产物自洽**（导出器 ↔ pin ✓、词汇唯一权威 ✓、能力对拍 ✓） | 这些对拍**两端都在 native** ✓ ⇒ 与本裁定无关 ✓，照旧执行 ✓ |
| **步骤改名等已落的事实** | 已落地且自洽 ✓ ⇒ 不回退 ✓ |

## 3 受影响的做法（逐条）

- **不再**为了 Kotlin 侧的比对而维护/重冻 `app/**` 与 `profile-core/**` 下的 `.tsv` 副本 ✓（待重写时一并处理 ✓）；
- **不再**把「Kotlin 侧是否已有对应枚举」列为设计的前置未核项 ✓（设计稿里此类条目改为「重写时处理」✓）；
- **不再**以「Kotlin 现在读什么」来决定 native 的形态（例如脚本面 `order` 行 ✓、能力两权威 ✓ 按设计推进）✓。

## 4 未定（不猜）

- Kotlin **重写的时间与范围** ✓ —— 未定 ✓；届时本 ADR 的第 1 条解除（对拍恢复）✓，第 2/3 条由新架构的设计重述 ✓；
- 重写是否需要 native 提供**另一套**导出面 ✓ —— 属重写设计 ✓，现在不预判 ✓。
