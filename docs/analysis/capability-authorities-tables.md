## 3b 三输入的判定表（R3）

三种事实：**必需/可选**（目录声明 ✓）× **已实现**（静态 per backend ✓）× **本设备可用**（运行期 ✓）。

| 必需性 | 已实现 | 本设备可用 | 结论 / 拒绝码 |
|---|---|---|---|
| **必需** | ✗ | — | **声明期 FAIL**（对拍红：声明 ⊆ 提供 被破 ✓） |
| **必需** | ✓ | ✗ | **运行期 `capability-missing`** ✓（这正是该码应有的触发条件 ✓） |
| **必需** | ✓ | ✓ | 可用 ✓ |
| **可选** | ✗ | — | 允许 ✓，但**被选择时具名拒绝** ✓（不静默 ✓） |
| **可选** | ✓ | ✗ | 允许 ✓，被选择时**运行期 `capability-missing`** ✓ |
| **可选** | ✓ | ✓ | 可用 ✓ |

**证伪（各一条）** ✓：① 把某能力从提供表删掉 ⇒ **声明 ⊆ 提供** 必须红 ✓；② 把某能力在设备事实里标为不可用 ⇒ 选择它时必须 `capability-missing` ✓（绿即 vacuous ✗）。
