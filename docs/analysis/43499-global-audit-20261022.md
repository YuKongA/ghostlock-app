# 43499 全局变量/常量审计（2026-10-22）

## 结论

- 攻击/会话状态已没有可写全局。
- `.data` 仍有 4 个标准日志库状态，这是接入 `general/gl_log` 后的明确例外。
- `.data.rel.ro` 有 5 组只读表；不是可写状态，但仍是编译期数据。
- 还有若干协议/平台常量未参数化，分 P0/P1/P2 列出。

## 1. ELF 数据符号

命令：

```text
llvm-nm -S --defined-only libghostlock43499.so
llvm-readelf -SW libghostlock43499.so
```

### `.data`（可写，4 个）

| 符号 | 归属 |
|---|---|
| `g_export_fd` | `general/gl_log.c` |
| `g_min_level` | `general/gl_log.c` |
| `g_timestamps` | `general/gl_log.c` |
| `g_start_ms` | `general/gl_log.c` |

这是日志库 DSO-local 状态，不是会话/攻击状态。`b/B=0` 仍成立，但
“绝对零可写全局”不再成立；如要恢复，必须把 gl_log 改成 session API。

### `.bss`（2 个）

| 符号 | 归属 |
|---|---|
| `__aarch64_cpu_features` | Android libc 启动期 |
| `__aarch64_have_lse_atomics` | Android libc 启动期 |

不是本项目状态。

### `.data.rel.ro`（只读，5 组）

| 符号 | 大小 | 说明 |
|---|---:|---|
| `known_offsets` | 0x3860 | 编译期内核 profile 表 |
| `g_profile_map` | 0x2e8 | JSON profile 字段映射 |
| `g_symbol_map` | 0xb0 | JSON symbol 映射 |
| `g_task_map` | 0xf0 | JSON task 字段映射 |
| `kernelsnitch_strings` | 0x30 | KernelSnitch 状态名 |

这些是 `const` 数据，加载后只读；不是可写全局。名字带 `g_` 但不应按可变全局处理。

## 2. 已清掉的最后两个硬编码

本轮顺手修掉：

- `fops.c` mcast fake BSS：`KIMAGE_TEXT_BASE` → `s->target.layout.kimage_text_base`。
- `perf_find_task` 候选下界：`0xffffff8000000000` → `layout.direct_map_base`，
  由 `child_pipes.direct_map_base` 携带。
- `payload_geometry` 的 TCP chunk bias：`0xe80` → `layout.skb_tcp_bias`。
- `glk_session` 的 page_shift/page_size：`12/4096` → `PAGE_SHIFT/PAGE_SIZE`。

## 4. 源码级全局检查

```text
文件级 static 变量：0（仅 static 函数/const 表）
攻击/会话可写全局：0
日志库可写全局：4
```

`Glk43499Session` 仍由调用方拥有；`Glk43499Runtime` 内所有 fd 都有 -1 sentinel。

## 5. 建议顺序

1. 统一 fake task offsets 默认表，消除 0x94/0x84 双源。
2. 把 `select_consumer_nice/burst_calls` 接进 config 并给默认值。
3. 把 perf ring/spin/candidate 常量放进 config 或平台常量。
4. 删除 `KERNEL_PAGE_SETUP_ATTEMPTS`、`PSELECT_ROUTE_NFDS`、`ORDER3_SIZE/SKB_SEND_SIZE` 等无活跃调用宏。
5. 若要绝对零可写全局，单独立项把 `gl_log` 改成 session/context API。
