# 判据 · 扩展点 · 技术债 · CBN（按审查原则 v0.2 改造）

> 分析类（≤8 KiB）。配套 [plan](handoff-payload-plan.md)、[b0](handoff-payload-b0-contract.md)、[b1b2](handoff-payload-b1b2-runtime.md)、[queue-schema](handoff-payload-queue-schema.md)、[batch-plan](handoff-payload-batch-plan.md)。依据：`docs/development/design-review-principles.md` **v0.2**（D1 / C2 / C3 / F2）。**本文是「判据形式 / 扩展点 / 技术债预判 / CBN」的唯一权威**。

## 1. 判据总则（D1 为准）

- **判据形式 = 黑盒 / 白盒 + 极端输入值**：
  - **黑盒**：外部可观测行为——命令行退出码与输出、wire 文档字节、日志行、标记文件、生成的 manifest/golden；
  - **白盒**：内部结构——单元测试、`static_assert`、编译期表断言、层表/账本、`nm` 符号检查。
- **只列极端输入值下的预期结果**：边界（0 / 1 / MAX）、空、超限、非法组合、越界数值、类型不符。
- **删除「绝对不可能发生」的用例**（不可达分支不测）。
- **不再要求为守卫/断言做造错（证伪）实验**——该要求自 v0.2 起为可选手段（AGENTS 同条与 `engineering-rules.md` **R10** 均保留原文并标注为可选）。
- **保留的真实门槛**（v0.2 未取消）：真机是功能唯一判据（R15）；失败数读 XML 全量（R17）；产物身份 + 新鲜度（R16）；具名诊断是契约（R11）；fail-closed（R12）。

## 3. 扩展点（C2：新增同类时改哪里 / 不改哪里）

| 结构 | 扩展场景 | 要改 | 不改 |
|---|---|---|---|
| `OpSpec` / `OpRegistry` | 新增 op | 注册表加一行 + `ParamSpec` + 能力/副作用位 | 分派代码、gate 主体、wire 键族 |
| 7 键队列元素 | 新增键（如诊断字段） | 成员表 `members` + Kotlin 镜像 + 对拍 | 元素物化逻辑（上限已留 5 键头寸） |
| payload 键（`backend.<id>.payload.*`） | 新增脚本/模块字段 | **三处同批**：manifest 新行 + golden（presence-gated）+ **Kotlin 白名单 `payload`**（`ProfileLayout.kt:182-183`/`:190` + `:620`/`:650`）| 既有行、无 payload 用例的字节 |
| 执行器（UserRoot/Umh/CredGrant/KernelCmdSet） | 新增执行器 | 枚举 + 构建期选择 + `executor-unavailable` 判据 | 运行期分派（单值、构建期定） |
| `Handle{kind,index,generation}` | 新增资源种类 | `HandleKind` + 探针产出点 | 句柄校验路径 |
| 脚本沙箱 | 新增宿主 API | API 白名单 + **受限副作用清单** + 评审 | 沙箱白名单（危险库永不注册） |

- **为何易扩展**：能力面/参数/句柄种类都是**表驱动 + 编译期**；新增同类只碰表与对拍，不碰运行期分派与 wire 布局。

## 4. 技术债预判（F2）

| 新组件/结构 | 未来可能新增的功能 | 预估技术债 | 偿还时机 |
|---|---|---|---|
| `OpRegistry` 表 | 运行期可插拔 op | 与「编译期锁定」冲突（R6） | 若确需 ⇒ 另立 ADR + 门禁 |
| 7 键元素 + `kMaxMapMembers=12` | 成员继续增长（>12） | 上限顶格 ⇒ 需再抬或改结构 | 第 3 次新增键时评估 |
| `slot.*`（有界 64、单次 run） | 跨运行持久变量 | 与「一处读取/生命周期」冲突 | 需求出现时另立设计 |
| Lua 沙箱白名单 | 新宿主 API | 能力面扩大 ⇒ 安全面回归 | 每次扩展过受限副作用清单 |
| payload 键（解冻期） | 插件/payload owner 解冻 | manifest/golden/白名单三处同批 | 解冻批次（见 plan D32） |
| gate 10 条原因 | 新原因 | 原因码是契约（R11）⇒ 只增不改义 | 新增时同批更新 kotlin strings |

## 5. CBN（成本权衡依据）

**CBN-1 编译期静态策略 vs 运行期虚接口**（route/op 分派）

| 字段 | 内容 |
|---|---|
| 决策点 | route/op 分派：编译期 `switch`+policy vs 运行期虚接口 |
| 备选 | ① 编译期静态（现状）；② 运行期虚接口/注册表（**更灵活**） |
| 收益 | ① PI 窗口内零间接分派（`nm` 无 `_ZTV*`，可机器验证）；② 每新增 route 仅加一个 policy 类型 |
| 成本 | ① 每新增 route/op 需改表 + 重新编译（**边际成本 = 1 表行 + 1 策略类型**）；② 引入虚表 ⇒ 违反 ADR-0004 且窗口内有间接调用风险 |
| 翻转条件 | 若出现「**运行期加载第三方 route/op**」的硬需求（无法编译期枚举）⇒ 改选 ②，且必须把间接分派移出 PI 窗口 |
| 结论 | 选 ①：边际成本可度量且低，② 的灵活性当前无需求方 |

**CBN-2 7 键扁平元素 vs 嵌套复合元素**（队列）

| 字段 | 内容 |
|---|---|
| 决策点 | 队列元素：扁平标量键 vs 允许嵌套 map/array |
| 备选 | ① 扁平（现状）；② 嵌套（**更灵活**，可表达任意结构） |
| 收益 | ① 元素只收标量 ⇒ 物化有界、可具名拒绝、与 wire 宽度表同构；② 表达力强 |
| 成本 | ① 新增键需动成员表 + 对拍（**边际 = 1 行 × 两侧**）；② 嵌套 ⇒ 深度/大小递归风险 + manifest 无法逐键描述 |
| 翻转条件 | 若出现「单个 op 需要结构化参数树」的硬需求 ⇒ 改选 ②，且必须给深度与字节双上限 |
| 结论 | 选 ①：边际成本低、可验证性强；结构化需求用**声明段**（参数块）承接 |

**CBN-3 双上限合并 vs 保留两名**（`kMaxMapMembers` / `kMaxCompositeKeys`）

| 字段 | 内容 |
|---|---|
| 决策点 | 元素 map 上限：合并为一个常量 vs 保留两道 |
| 备选 | ① 合并（删 `kMaxCompositeKeys`）；② 保留两名（**更“稳”**：改动面小） |
| 收益 | ① 一处权威（R1）⇒ 改一处即全链路生效；② 不动现有代码 |
| 成本 | ① 需改 1 处使用点（`glkv3_parse.cpp:168`）；② **两处不同步 ⇒ 顶格无头寸且解码层先失败**（已实测） |
| 翻转条件 | 若两处上限**确需不同**（如物化层更严）⇒ 保留两名但必须写明关系与判据 |
| 结论 | 选 ①：② 的成本已实际发生（一次真实缺陷），① 边际成本 = 1 行 |
