# CPP17 真机门禁：首次冷机 W1 窗口 kernel panic（别名收归构建）

- 构建：APK 324（覆盖安装）；native `55863311e8e551df`（`g_heap_context`/`g_target_profile`/`g_resolved_addresses`
  三个引用别名收归 + `activate_prebuilt_page` 内联；与门禁基线 `18fe119c` 全函数对比：11 个函数 shape 变化、
  关键函数外部调用序列一致，详见 `native-cpp-migration-plan.md` CPP17）
- 运行：Direct / Multicast，冷启动（进程日志 `ghostlock-20260918-103956-772-0-direct.log` 被 panic 截断为空白）
- pstore：`dmesg-ramoops-0`/`-1`（本次为**明文**，非加密 `.enc.z`）

## 判定

- 与 `KERNEL-PANIC-01` 同型：攻击进程自身线程 `sched_setattr → rt_mutex_adjust_pi` 遍历 PI 链时读 NULL
  （`CPP12s` 为 `+0x1a0`，本次 `+0x1b0`；触发者同为攻击进程内线程）。
- 时间线：冷机第一次运行（10:39:56 起）在 W1 PI-route 窗口 panic，设备自动重启；
  重启后 10:41:38 的第二次运行完整 PASS（`CPP17-20260918-multicast-pass.native.log`）。
- 归因：同构建 panic→PASS，符合 `KERNEL-PANIC-01` 的"环境/时序、与布局无因果"口径；本次仅 1 个
  成功样本且为 panic 重启后的运行，**尚不满足"成功冷机"门禁条件**，需继续冷机复跑。
