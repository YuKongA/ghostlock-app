# 附件：中途切换 route 的写法（待裁 · 2026-10-08）

> 分析类（≤8192 B）。**配套**：[lua-surface-design](lua-surface-design.md)（§1 暴露面表 · §6 待裁）。来源：用户提问「**中途切换 route 怎么办，新建 backend 吗**」+ Lead 答复框架。

## §A1 结论（一句话）

**不新建 backend**：**backend = 漏洞（cve id）**，**route = 同一漏洞的不同打法**；**换路发生在同一 backend 的句柄上**。

## §A2 约束（三条，决定写法）

| # | 约束 | 对写法的影响 |
|---|---|---|
| **C1** | **route 生命周期 `prepare → execute → disarm → destroy`** | **两条 route 不得同时在窗口里活着** ⇒ 切换只能**串行**（先 disarm 旧的，再 prepare 新的） |
| **C2** | **窗口内零 Lua** | 切换**只能发生在窗口之间**（脚本在窗口外 stage，实现层在窗口之间完成 disarm/prepare） |
| **C3** | **「禁止任何运行时回退」**（用户早先裁定） | **自动 fallback 不允许**；**换路必须显式表达**（谁换、换成什么，写在计划里） |

## §A3 候选写法（三条 + 一个否决项）

| 候选 | 写法 | 代价/风险 | 判定 |
|---|---|---|---|
| **O-a** | **`b:use_route(name)`**（**Lead 推荐**）：单句柄 + staged 动作；runtime 在**窗口之间** `disarm` 旧 route → `prepare` 新 route | 需要 runtime 在窗口间实现一次切换原语；与 C1/C2 完全兼容 | **推荐** |
| **O-b** | **两个句柄**（同一 backend 两个 route 句柄） | 必须定义「**同一时刻只有一个活跃 route**」并加判据，否则违反 C1 | 可行但约束负担高 |
| **O-c** | **计划级路线段**（在计划里引入第二层分组） | 与「**计划 = 顺序**」的单一权威**有张力**（引入第二层顺序来源） | 需举证 |
| ❌ | **自动 fallback**（失败自动换 route） | 与 **C3「禁止运行时回退」**冲突 | **不允许**；要用必须**用户明确改口 + 强制越权登记**（技术债） |

- **判据（选定后）**：白盒 = 计划里**显式**出现换路动作（无隐式 fallback，grep 无自动路径）· `disarm`/`prepare` 之间**无窗口**（生命周期串行）· 窗口相位内**零 Lua**；黑盒 = 换路点前后各一次写操作均成功且审计行连号；极端值 = 换到不存在 route（具名拒绝）· 换到同一条（幂等或拒绝，二选一并断言）。
