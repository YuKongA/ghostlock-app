## 剩下的唯一解释

```
base = align_base(leaked, align_region_size)   （prepare_page.hpp:478 ✓）
⇒ 泄漏（snitch 的结果）对**同一个 spray 状态**是**确定**的 ⇒ 重跑准备只会得到同一个 base ✗
⇒ 要让 base 变，必须**换掉那个状态本身** ✓
```

## 因此：三槽模型是必需，而不是可选

- 退役：`Current` / `Quarantined` / `Prebuilt` 三槽 ✓（`PayloadPageState` ✓）；
  "预置 → 激活"＝**先建第二页 → 销毁第一页 → 搬回 current** ✓ ⇒ 每次都真的换了状态 ✓；
- 本树：只有一个"每次重开"的准备 ✗ ⇒ 状态不变 ⇒ base 不变 ✗；
- ⇒ 结构改动的**规格**（属攻击关键路径 ⇒ 先计划 ✓）：
  1. 准备结果携带**状态句柄**（本树的 `PrepareReport` 已握有 shaping/资源 ✓ ⇒ 需要的是"搬迁/销毁"能力 ✓）；
  2. 提供 `quarantine()`（搬进隔离槽 ✓）与 `release()`（销毁 ✓）两个动作 ✓；
  3. 奇偶不合格 ⇒ `quarantine()` 当前状态 ⇒ **再准备**（新状态 ✓）⇒ 合格则 `release()` 旧的 ✓；
  4. 判据：三步各自拿到**奇** base（`accepts=1` ✓ 不依赖重试 ✓）⇒ 随后回到 `uid=0` ✓。
