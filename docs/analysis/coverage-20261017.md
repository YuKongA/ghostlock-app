# 覆盖率分析（2026-10-17，删除 vendored 库与 JNI 不可达旧代码之后）

## 1 范围与方法

- 宿主构建插桩：`core/CMakeLists.txt` 的 `GL_COVERAGE`（clang `-fprofile-instr-generate -fcoverage-mapping`）。
- 被测对象：`ctest` 全部 **92** 个宿主测试（`GL_JNI=OFF`；JNI 目标只在 Android 构建里出现）。
- 复现：

```bash
cmake -S core -B build/cmake/coverage -DGL_COVERAGE=ON -DGL_JNI=OFF -DCMAKE_BUILD_TYPE=Debug -DGL_TESTS=ON
cmake --build build/cmake/coverage -j 8
mkdir -p build/cov && rm -f build/cov/*.profraw
LLVM_PROFILE_FILE=$PWD/build/cov/%p.profraw ctest --test-dir build/cmake/coverage -j 8
xcrun llvm-profdata merge -sparse build/cov/*.profraw -o build/cov/merged.profdata
xcrun llvm-cov report $(for f in build/host/*_test; do printf -- '-object %s ' $f; done) -instr-profile=build/cov/merged.profdata
```

## 4 怎么读这些数字

- 0% 的 `.hpp` 多是静态表/常量目录（`module_facts.hpp`、`kind.hpp`、`sentry_hook.hpp` 的常量），宿主测试不触达它们是结构性的。
- `jni/api_43284_device.cpp` 6.78% 是设备侧 JNI 入口：只在 Android 真机链路执行，覆盖率要看真机门禁，不看主机插桩。
- `encap_peer.cpp` / `multicast_route.hpp` 0% 同理（真机 landing 路径）。
- 覆盖率不是验收判据；判据仍是 AGENTS §8（宿主测试 + Android 零告警 + 真机门禁）。本表只用来找「该有测试却没有」的空白。
