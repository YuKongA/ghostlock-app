--- 本轮问题追因与复核（2026-10-29）---

根因核实：基线 `backend/43499glued/BackendExecGlue.kt` 中 `ExecGlueSpec` 把 `CVE-2026-43499` 的 titleRes 和 Ready readiness 赋给所有子类；因此 43499 Glued、43284 Glued、原版 43499 曾出现三个 43499 标签。旧 selector/selection 没有 disabled allowlist，故原版后端和 Lua 也能选。现已移除该抽象；两个 Glued spec 各自直接实现 BackendSpec、声明独立 displayNameRes 和 readiness。当前 source/DEX 都没有 `BackendExecGlue` / `ExecGlueSpec`。保留的 `backend/core/ExecutableBackendProcess.kt` 是两条 Flow 共用的执行 helper；Gradle `buildExecGlue` / `packageExecGlue` 是构建和打包 upstream ELF 的 task，均非 backend declaration/base class。

本轮代码变化：`Backends.isSelectable` 从 Set membership 改为 `===` singleton 比较，防止动态 Lua spec 通过自定义 equals/hashCode 冒充 Glued；`DynamicBackendsTest` 增加 equality-impostor 回归用例；BackendSpec selector KDoc 改为实际使用的 displayNameRes。
