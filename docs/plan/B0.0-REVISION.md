## R1 契约中性化

- **目标**：`contract` 只放**中性面**——op token、`WriteOutcome`、句柄、诊断；**参数结构由各 backend 自持**（CVE-2026-43284 的 page-cache 原语必须可表达）。
- **依据**：`docs/analysis/handoff-payload-b0-contract.md` §3/§4；本轮用户裁定（**无虚基类**；token + `ParamSpec` → op 内强类型）。
- **产出**：中性面清单（host 可编译）+ 各 backend 参数结构 + 概念约束 `static_assert`。
- **判据**：白盒 = 层表 **0 越层边**、窗口 TU 禁 include、概念 `static_assert` 可失败；黑盒 = 同一份文档在**两个 backend** 下都通过编译期校验；极端值 = 空参数 / 超上限参数 / 未注册 token ⇒ 具名拒绝。
- **门禁**：G1（宿主）· **动攻击路径：否**（仅类型与契约面）。

## R2 Lua↔C++ 边界

- **目标**：`OpRegistry` = **脚本唯一接口权威**；`orchestrator` **改名 `composition_root`**，职责收敛为「实例化 + 构造绑定 + 编译期校验」，**执行顺序归计划**（不再由它承担）。
- **依据**：`docs/analysis/handoff-payload-b1b2-runtime.md` §B1.1/§B2.2；`core/src/pipeline/orchestrator.hpp:13-22`（现有注释即「在敏感窗口外校验选择 + 直接模板调用分派」）。
- **产出**：改名 + 职责边界声明（顺序表达移到计划/队列）+ 触点清单。
- **判据**：白盒 = 全仓旧名 `orchestrator` 残留 **0**（grep）· `composition_root` 内**无顺序分支**；黑盒 = 换序即换行为（同一文档顺序改变 ⇒ 执行顺序随之改变）；极端值 = 空队列 / 单条目 / 顺序颠倒。
- **门禁**：G1 · **动攻击路径：否**（若改名触及 M5 对拍资产 ⇒ 同批更新对拍，仍不动执行语义）。

  - **(b) 全表必填**：manifest 全字段必填（含未选中）⇒ **既有 profile 需同批迁移**，App 需补全字段。

## R5 窗口内 `sched_setattr`（**延期**：触发 = B0.1→B3 完成后评审）

- **状态（2026-10-08 台账更新）**：**延期，保持现状**（不改代码）—— **触发条件** = **B0.1→B3 全部完成后**评审 A/B/C 三方向；届时按本节判据 + **G1+G2** 执行。下表作为该次评审的**材料**保留。

- **背景（实证）**：两份独立 panic 栈均指向窗口内 `sched_setattr` → `rt_mutex_adjust_pi`（`docs/analysis/pi-window-constraints.md` §1）；native 侧调用点：`core/src/support/util.cpp:76-88` → `core/src/race/threads.cpp:144`。
- **三个方向（各自影响面与所需门禁；本文不选）**：

  | 方向 | 做法 | 影响面 | 所需门禁 |
  |---|---|---|---|
  | **A 保留** | 窗口内调用不变 | 不改代码；panic 风险有据（§1） | **G1+G2**：冷启多次 + dmesg 采样 |
  | **B 移出窗口** | nice 调整移到 waiter 停泊**前/后** | 改 `threads.cpp` 时序；需重验成功率 | **G1+G2**：单 route 通过 + 成功率≥基线 |
  | **C 移除** | 删除该 nice 调整 | 可能影响 6.1 compact 的成功率（源码注释） | **G1+G2**：成功率对比（下降则不可接受） |

- **产出（选定后）**：实现改动 + 真机门禁记录（`docs/analysis/device-gates/*.md`）+ pi-window-constraints §2 白名单同步。
- **判据（选定后）**：黑盒 = dmesg 不出现 §1.1 栈 **且**成功率≥基线；白盒 = 窗口内无被禁调用（B/C）。极端值 = waiter 存活期两端（`(calls%19)+1`，`threads.cpp:141-144`）。
- **门禁**：**G1+G2（真机）** · **动攻击路径：是** ⇒ **未选定前不得改**（本工作包只登记，不执行）。

## R10 Lua 配置结构设计（**待用户裁定**）

- **目标**：给出 **2–3 个 Lua 配置结构形态**及各自代价，供用户裁定；**裁定同时关闭 R3**（默认值必填范围）。
- **依据**：用户裁定（Lua 5.4，D22）；`handoff-plugin-lua.md`（控制面）；`handoff-payload-b1b2-runtime.md` §B2（沙箱/预算）；principles **C3**（编译期收益须与成本权衡）。
- **产出：三个形态选项（含代价；本文不选，交用户裁定）**

  | 形态 | 结构 | 收益 | 代价 / 风险 |
  |---|---|---|---|
  | **L-A 单脚本返回表** | 一个 Lua 脚本返回 queue/params 表 | 改动最小、与现 wire 同形 | 无静态类型：校验靠运行期（gate 只能做文法 + 能力检查）⇒ 错误晚发现 |
  | **L-B 脚本 + 显式 schema** | 脚本 + 声明式 schema（`ParamSpec` 表），gate 期静态校验 | 与 `OpSpec`/`ParamSpec` 对齐；可具名拒绝 | 同一参数两处描述 ⇒ **每 op 边际成本翻倍** |
  | **L-C 数据优先 + 扩展点** | 主体仍是 HOCON/wire，Lua 只做条件/计算 | 迁移成本低、可回退 | 两种表达并存 ⇒ **双读取路径风险**（须同批逐值对拍 + 声明回退） |

- **判据（落地时用）**：黑盒 = 同一意图产出**逐字节可复现**的 wire；白盒 = 无第二条读取路径（或已声明回退 + 逐值对拍）；极端值 = 空脚本 / 语法错 / 超预算 / 引用不存在参数 / 表超深。
- **门禁**：**G1 + 用户裁定**（形态选择含产品取舍，不由技术判据单独决定）· **动攻击路径：否**（仅配置结构）。
- **与 R3 的关系**：R3 的「必填范围」取决于本项形态 —— **L-B 倾向全表必填**（schema 已声明全部字段），**L-A / L-C 倾向被选中路径必填**；⇒ **R10 裁定后 R3 立即解阻**。
