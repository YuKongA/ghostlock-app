# 43499 · 5.10 攻击路径单独适配计划（select_stack）

> 状态：草案 / 待实施。日期：2026-10-29（host America/Toronto）。
> 触发：用户裁定「5.10 可能需要单独适配攻击路径」，参考：
> - PR：<https://github.com/YuKongA/ghostlock-app/pull/403>（“Stop the select route from destroying unrelated file descriptors”，注明 **preliminary fix for 5.10 series kernel support**）
> - Issue 评论：<https://github.com/Haoyu-UT/ghostlock-app-diting/issues/2#issuecomment-6432332703>（“a fix is needed for 5.10 or any other profile using select_stack + compact_waiter=2”）
> - 上游 5.10 profile：`ghostlock-app/app/src/main/assets/kernel_profiles/5.10.236-*.conf`（Xperia 5 IV，5.10.236）
> - diting 5.10 profile：`ghostlock-app-diting/.../5.10.236-android12-9-00003-*.conf`（Redmi K50 Ultra；**select_stack + waiter_shift=-2 + compact_waiter=1**，设备实测成功）
> - diting `docs/analysis/payload-page-option2-plan.md`（lock anchor / Option 2）

## 1. 结论（为什么 5.10 不能用 mcast/legacy2 race）

1. **multicast 在 5.10 几何不可行**：diting 5.10 profile 头注明 —— “multicast_waiter is geometrically infeasible on this build (its copy window ends **0x48 short** of the waiter slot)”；其 profile 注释与 kprobe 也确认 `futex waiter == pselect stack_fds`。这与我们 mondrian 上 mcast/actor 的 pre-carrier hang、one-shot 无真实写入一致。
2. **5.10 正确路线 = `select_stack`（pselect）**：`waiter_shift = -2`，`compact_waiter = 1`，三组 fd_set 词直接覆盖内核栈上的 stale waiter。
3. **必须同时修 select route 的 fd 破坏问题（PR 403）**：pselect 前会把 0..319 中 bit 置位的 fd 全部 `dup2` 到 route 读端；不备份/恢复会替换掉 app fd 与 **victim 协议 pipe**，导致 victim 提前退出 / W2 EPIPE（PR 403 的根因描述）。
4. **5.10 需要 lock anchor（Option 2）**：select route 的 fake waiter `lock` 字若指向回收页，walk 可能 foreign-tree 乱走导致 RCU stall/重启；5.10 实测稳定做法是把 lock 指向**镜像内全零可写 .bss**（`lock_anchor_image/bytes/stride`），walk 在第一次判断即安全退出，写仍由栈 waiter tree entry 完成。
5. **cred 结构 5.10 与 5.15 不同**：本机 `/sys/kernel/slab/cred_jar/object_size = **168**`，我们 debug-mondrian.conf 的 `copy_size=176 / caps_offset=48 / caps_count=3` 是错的（W2 会失败）。5.10 实测值：`copy_size=168, usage_offset=0, usage_value=256, caps_offset=40, caps_count=5, caps_value=0x1ffffffffff`。

## 5. 分阶段实施（一批一类事；每批门禁 + 真机证据）

### S0（诊断，无行为变更）
- 在 pselect primitive 下复跑 E1（cold），记录 `E1|` 行 + pselect carrier prepare/trigger 的 step/errno；定位 `chain=skipped` 的 clean-fail 点（landing page-accept? carrier prepare? fd reserve?）。
- 产出：失败点 file:line + 最小修复候选。

### S1（PR 403 移植：fd 快照/恢复 + victim pipe 高位）
- Native `carrier_pselect.c`：`dup2` 扫描前快照每个目标 fd（F_GETFD→F_DUPFD_CLOEXEC），pselect 返回后恢复（含 CLOEXEC）；`disarm/restore` 幂等；forced slot（NFDS-1）纳入快照。
- Kotlin victim transport（`ProcessVictim`/`ProcessVictimSession`/`Cve43499JniVictim` 视实现）：父端 `task_read/cmd_write/uid_read` 用 `F_DUPFD_CLOEXEC(NFDS+64)` 上移；失败则 spawn 失败（fail-closed）。
- 单测：fd 快照恢复的 Native host test / Kotlin 逻辑测试；双构建。

### S2（5.10 profile 正确性）
- debug-mondrian.conf：`cred` 改 5.10 值；`generator.pselect` 调参（先上游默认 50ms enter，后按 E1 再调）；显式 `compact_waiter = 1`（若解析键缺失则新增 profile/配置键）。
- 校验：Kotlin config 单测（fail-closed）、host ABI 布局测试。

### S3（lock anchor / Option 2）
- 新增配置键：`route.select_stack.lock_anchor_image/bytes/stride`（u64/uint，缺省=旧行为）。
- **为本机 5.10.252 选取 anchor**：从 boot.img 解出 vmlinux（或 kallsyms+已知零 .bss 符号），找 `dump_skip` 内 `zeroes` 或等价全零 .bss 区域；确认为可写、零、无读写者；记录 offset/bytes/stride。
- Payload/generator：select 路线的 waiter `lock` 字写 `symbol_image(lock_anchor_image)`，其余不动；保留回退（缺键=旧行为）。
- 单测：host 字节向量（anchor 字替换）；E1 前静态证据。

### S4（真机 E1 → W1b → W2）
- cold E1（select_stack）：判据 = W1 写落地（Enforcing→Permissive 由外部 ack 证据）或 clean fail 且无 panic；连续 5 次统计。
- 通过后 W1b/W2（cred 5.10），再 W3。

### S5（门禁/冻结）
- 全量单测、双构建、`git diff --check`、ABI 布局、门禁文档；关闭 mcast 默认（仅保留显式实验/非 5.10 配置）。

## 6. 判据（每阶段）

- S1：fd 快照恢复单测通过；双构建 EXIT=0；无行为变更（默认 mcast 不受影响）。

## 7. 风险

- lock anchor 选取错误 ⇒ kernel freeze/panic（有先例：foreign-tree walk）。必须静态证据 + 先单发/保守尝试。
- PR 403 移植影响 pselect 热路径（fd 快照开销）→ 只在 select route 生效，mcast/tcp 不受影响。
- `compact_waiter=2` 的语义在公开代码中未出现（上游仅按 0/nonzero 处理）；若 issue 指的是另一种布局，需要额外证据，不猜。
- 5.10.252 与参考 5.10.236 的 stack 几何可能不同：waiter_shift 必须由本机 boot.img/kprobe 验证，不直接照抄。

## S3 实施记录（task-134，2026-10-29）

### 本机 anchor 静态取证（boot img）
- 输入：`/tmp/mondrian-boot_b.img`，201,326,592 B，sha256
  `9448f9d78460a07a2be3abb71786c75178c2c78a7fb394e3beb8d91fe26a1713`。

  - `cargo run --release --example bss_xref -- /tmp/mondrian-boot_b.img dump_skip.zeroes`
  - `cargo run --release --example disasm_func -- /tmp/mondrian-boot_b.img dump_skip`

- 关键事实：
  - kallsyms `_text` link base = `0xffffffc008000000`；`dump_skip.zeroes` 镜像相对
    offset = **`0x27dc7c8`**（十进制 41797576），绝对 link VA
    `0xffffffc00a7dc7c8`；kernel_len=0x2a625fc。
  - `.bss` = `[+0x278d000, +0x2826038)`，可写起点 `__end_ro_after_init=+0x229ac70`；
    anchor 在可写 `.bss` 内。
  - `dump_skip.zeroes` 0x1000 字节在镜像中**全零**（first_nonzero=None）。
  - 下一符号 `core_uses_pid` = `+0x27dd7c8`（=anchor+0x1000），即数组恰 0x1000 字节。
  - 8-byte 全镜像字面量扫描：**0 个**指向 anchor 的指针字面量（`literal_hits=0`）。
  - 直接引用（`bss_xref dump_skip.zeroes`）：仅 **2 个 adrp 命中**，均位于 `dump_skip`
    （+0x70/+0x1a4），均 `adrp 0x27dc000; add #0x7c8` 后 `mov x1,x22; bl dump_emit`；
    **无 store** ⇒ 只有 bulk-copy read（设计中的 needs-review 语义）。
  - `--anchor-scan` 的 page-level 参考扫描会把相邻页符号（如 `insert_header` 对
    `+0x27dd000` 页的 adrp）误记到候选范围，报告 unsafe；手工逐命中核对后以
    `bss_xref`/disasm 的直接引用证据为准（工具自身设计也声明 page-scope 近似的限制）。
- stride：`0x20`（32）。证据来自 diting 5.10 `5.10.236` profile 的 hand-measured
  值（`lock_anchor_stride=32`）及其 kprobe 记录（lock-relative 写只到 +0x08/+0x10，
  无 +0x18 之后访问 ⇒ 0x20）；**本机 image 未独立推导 stride**（diting tool 明确
  不推导 stride；本机无 BTF），因此 stride 的本地真值仍 UNVERIFIED；bytes/stride
  仅作配置范围校验，当前 payload 只替换一个 lock 字。
  ⇒ 建议 anchor triple：`image=0x27dc7c8`（41797576）、`bytes=4096`、`stride=32`。
