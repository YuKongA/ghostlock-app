## setsockopt 链（IPv4 MCAST_BLOCK_SOURCE stamp）

| 函数 | 帧大小 | 证据 |
|---|---:|---|
| `__arm64_sys_setsockopt` | `0x10` | `stp x29,x30,[sp,#-0x10]!` |
| `__sys_setsockopt` | `0x80` | `sub sp,sp,#0x80` |
| `sock_common_setsockopt` | `0x40` | `sub sp,sp,#0x40`（CFI 检查内联，无额外帧） |
| `udp_setsockopt` | `0x10` | `stp x29,x30,[sp,#-0x10]!`，`bl ip_setsockopt` |
| `ip_setsockopt` | `0x290` | `stp x29,x30,[sp,#-0x60]!` + `sub sp,sp,#0x230` |
| **合计** | **`0x370`** | — |

- `ip_setsockopt`：`add x0, sp, #0x18` + `mov w2, #0x108` → `greqs = sp+0x18`，拷贝窗口 `0x108`。
- greqs 深度 = `0x370 − 0x18 = 0x358`。

## futex 链（waiter 分配）

| 函数 | 帧大小 | 证据 |
|---|---:|---|
| `__arm64_sys_futex` | `0xa0` | `sub sp,sp,#0xa0`；`bl do_futex` |
| `do_futex` | `0xd0` | `sub sp,sp,#0xd0`；`bl futex_wait_requeue_pi` |
| `futex_wait_requeue_pi` | `0x1c0` | `sub sp,sp,#0x1c0`；`add x9, x27, #0x18`，`x27=sp+0x28` |
| **合计** | **`0x330`** | — |

- waiter 栈局部：`x27 = sp+0x28`；`x9 = waiter+0x18` 与 BTF `rt_mutex_waiter.pi_tree_entry=0x18`
  一致 → waiter `sp+0x28`。
- waiter 深度 = `0x330 − 0x28 = 0x308`。

## `kernel_phys_load` 静态提取（已得）

`xbl_config.img` 其实是 ELF，内嵌 FDT 不含 memorymap（故 extractor FDT 解析失败）。改为解出 bootloader 分区并读平台内存映射：

- `payload.bin` 含 `xbl` / `abl` / `uefi` 分区；用工具解出后，`uefi.img`（AArch64 ELF）内含字符串：
  `0xA8000000, 0x10000000, "Kernel", AddMem, SYS_MEM, SYS_MEM_CAP, Reserv, WRITE_BACK_XN`
- 即保留给内核的物理区间基址 → **`kernel_phys_load = 0xA8000000`**（size `0x10000000`）。SoC 串为 `SM7550`。
- 与内置 QC 默认 `0xA8000000` 一致；静态可确定（非猜测）。

## `fake_*` 静态候选

- 宿主符号 `offset.mcast_fake_bss` = `z_pagemap_global` @ `+0x3103988`。
- 下一个符号 `erofs_debug` @ `+0x3107988` → `z_pagemap_global` 之后有 **`0x4000` 的 BSS 空洞**。
- A301SO 布局（`fake_lock=+0x1200`、`fake_task=+0x3200`、`lock_slots=+0x80`、`count=12`、`stride=8`）
  全部落在该 `0x4000` 内，且 `z_pagemap_global` 是 8 字节指针（其后为未命名的 BSS/对齐空间）。
- 因此 **沿用 A301SO 的 fake 布局作为候选**；仍属“静态选定、未在本机跑通”，须真机跑通 multicast 路由后方可确认不被内核覆盖。
