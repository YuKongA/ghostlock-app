# 既有 Bug 发现记录（2026-09-26，multicast 实验）

> 本记录只汇总**在现成代码里被发现、尚未在主线修复**的缺陷，供后续按攻击关键路径流程处理。
> 相关复现与结论见实验分支 `exp/multicast-w1`（含 `multicast-dynamic-page-plan.md` 的
> E1/E2 实测节与 `B-GROUP-20260926-multicast-dynamic-resident-fail.md` device-gate）。

## BUG-1：`multicast_resident` 无法从 profile 启用（配置解析路径错误）

- **现象**：任何 profile 都无法让 native 走 resident multicast；5.15 永远走 one-shot。
- **根因**：`MulticastConfig` 传入的 `multicast_resident` 经 `ProfileResolver.nativeValue`
  落到**顶层** `profile["multicast_resident"]`（末尾 `getLongAt(path)`），而
  `validateMerged` 的 `KnownTopLevel` **不允许顶层键**；route 分支内的
  `route.<name>.multicast_resident` 没有任何读取路径 → 值恒为 0。
- **验证**：把 `multicast_resident = 1` 加到 `route.multicast_waiter` 后，native 仍打印
  `W1: SELinux attempt 1/1`（one-shot）且无 `resident writer ready`。
- **影响**：5.15 只能走概率性 one-shot，W1 不稳定（见 BUG-2）。
- **修复**：`ProfileResolver.nativeValue` 增加 `multicast_resident` → `route.<name>.` /
  `fallback.route.<to>.` 的映射（实验分支 `a158bdc`）。主线未合。

## BUG-2：one-shot 的 W1 是概率性的（承载页 bit16）

- **现象**：`--mcast-one-shot` 下 W1 有时 `4/4` 承载页全被拒 → `Write 1 failed`；有时第 4 次
  命中 → `Write 1 complete`（并最终拿到 root）。
- **根因**：W1 要求 `payload_write_layout_accepts_page` 满足
  `(right = page_base + 0x100) >> 16 & 1 == 1`（保护 `selinux_state.initialized`）。one-shot 的
  承载页来自回收页，地址多为 `0x10000` 对齐（低 16 位为 0）→ bit16 恒 0 → 被拒；只有少数
  非对齐页才通过。因此 W1 成功与否取决于运气，而非几何。
- **影响**：one-shot 不能作为 W1 的可靠路径。
- **状态**：待设计（one-shot 仅适合 W2/W3，或需为 W1 选/构造 bit16=1 的承载）。

## BUG-3：resident 在 A301SO 上 W1 15/15 写不中（疑似回归，未解释）

- **现象**（修好 BUG-1 后）：`5.x resident writer ready bss=…da20c0 lock=…32c0 task=…52c0`
  （几何 = `z_pagemap_global+0x1200/+0x3200`，与历史一致），`W1 attempt 1/15`；但 15 次全部
  `resident write 0x…54000 -> 0x…ad88 ret=0` 却写不生效 → `Write 1 failed`。
- **要点**：`ret=0` 只表示 `sched_setscheduler` 状态切换成功，不代表 PI 写命中；历史（同机、
  同几何）曾是稳定 resident 成功路径，故疑似重构后回归，或当前环境（KernelSU 已加载/非冷机）
  干扰。
- **待做**：冷启动（KernelSU 未加载）复验；无效则按攻击关键路径排查 resident W1
  （BSS `fake_lock` 是否被占用、stamp/PI 写是否命中），对照历史成功版本，走 `cmp_disasm` + 门禁。

## BUG-4：`profile is unavailable` 掩盖“没有匹配到 profile”

- **现象**：设备 release 无匹配 profile 时，只报 `profile is unavailable for <release>`。
- **根因**：`runExploitBinary` 只检查 `invalidPaths`，未检查 `hasProfile`；`resolve` 返回 null
  时 `nativeDocument` 为 null，落到该模糊错误。
- **修复**：已在主线 `acda601`——记录 `hasProfile/invalid` 并给出
  `no profile matched …; import and select it` 的可操作错误。**已修**。
