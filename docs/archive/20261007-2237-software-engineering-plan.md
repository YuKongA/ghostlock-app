# GhostLock 软件工程规划（守则驱动）

> 依据：《软件工程教程》§1.8（BOEHM 七条原理 + 第八条二八定律）、§2.9（开发模型选择）、§5.1–5.6（软件策划：目的/输入输出、过程与策划活动、规模成本资源估计、风险分析、跟踪监督、策划文档与管理）。
> 范围：**只做规划与规则**；本文件**不改任何代码**。规则见 `docs/development/engineering-rules.md`。
> 日期：2026-10-07

## 0. 依据与不做项
- **做**：阶段划分、批次准入准出、二八预算、版本控制、阶段评审、文档策略、小组规则、度量与改进、风险与止损。
- **不做**：不改代码、不改资产、不删旧文档（删除属"取代"动作，见 §7，需评审批准后执行）。

## 1. 开发模型选择（§2.9）
| 候选 | 结论 | 理由 |
|---|---|---|
| 瀑布 | ✗ | 需求不稳定（内核适配逐 release 变化）；上游不可控 |
| 纯敏捷/XP | ✗ | 单件产出、失败代价高（可 panic）、"小步快跑"与 N2（不可逆段）冲突 |
| 螺旋 | △ | 风险驱动的思想吸收，但完整螺旋对单人研究项目过重 |
| **迭代 + 强阶段门（选定）** | ✓ | 每阶段一个小增量，**阶段门 = 真机判据 + 评审**；不可逆段只在阶段门内一次执行 |

## 2. 阶段划分（阶段 = 评审单元，§1.8①）
> 每阶段五要素：目标 / 输入 / 输出 / **准出判据** / 评审点。**一次只开一个阶段**。

| 阶段 | 目标（对应自审查 P#） | 输出 | 准出判据 | 评审点 |
|---|---|---|---|---|
| **S0 收口** | 清除全部临时物，建立可交付基线（§1.8③） | 无临时物的树 + 基线清单（文件+指纹） | 临时物计数 = 0；树可构建；基线清单逐项指纹核对通过 | 用户确认基线 |
| **S1 读取路径唯一化（P2）** | 同一数据只留一条读取路径 | 唯一读取点 + 同批等价对拍（若必须并存，声明降为回退） | **真机判据**：目标组合端到端通过；对拍逐值等价 | 用户评审 + 真机记录归档 |
| **S2 契约面集中（P1）** | 每个事实一处权威，其余机器生成 | 权威表 + 生成的清单（逐字节对拍） | 清单与权威双侧逐字节一致；无手抄表 | 用户评审 |
| **S3 业务层切分（P3）** | 按功能内聚切分，控制器退化为编排 | 模块边界图 + 接口清单 | 单文件 ≤400 行；跨模块仅数据耦合；行为不变（回归判据全绿） | 用户评审 |
| **S4 文档与判据分层（P4/P7）** | 规格唯一、分析只留"为何"、判据分两类 | 三类文档索引 + 取代清单 | 单篇体量达上限；旧文档**被取代**而非并存；索引唯一入口 | 用户评审 |
| **S5 删除纪律与契约机器化（P5/P6）** | 消除历史层积与手工同步 | 删除清单 + 沿革说明（一句） | 无"先加后删"残留；全部跨语言表为生成物 | 用户评审 |
| **S6 环境与运维（噪声降级）** | iCloud 冲突副本、设备 PM 破损态等环境问题 | 运维条目 + 复现步骤 | 每条有独立复现与判据；**不混入功能批** | 用户确认 |

## 3. 二八预算（§1.8⑧）
- 本项目 **80% 的架构收益集中在 S1（P2 读取路径唯一化）**（自审查 §4.3：本会话 bug 家族全部源于双读取路径/双权威）。
- 故：**用开始的 ~20% 时间完成 S0+S1**（= 80% 进度）；余下阶段按长尾处理，**预留 80% 时间**。
- 任何阶段若超出预算 ⇒ 触发 §10 止损，回到 S1 复核，而非继续加范围。

## 4. 批次规则（准入 / 准出）
**准入**：① 本批只服务**一个**阶段目标；② 写范围文件清单已列出且**互不重叠**；③ 判据（离线/真机）已预先写明；④ 若含临时物 ⇒ **同批登记移除计划**。
**准出**：① 判据全绿（含真机，若该批触及攻击路径）；② 临时物计数 = 0；③ 树可构建；④ 基线清单更新并核对指纹；⑤ 若含结构变更 ⇒ 同批更新 UML 与沿革（一句）。

## 5. 版本控制与基线（§1.8③）
- **基线** = 一个阶段准出时的树状态 + 文件指纹清单 + 该阶段判据记录。基线一旦建立，**不得悄悄漂移**。
- **提交**：每阶段一次，**须用户批准**（沿用"未经要求不 commit"）。
- **临时物零容忍**：诊断打印、探针标记、对照实验改动**不得进入基线**。
- **产物可丢弃**：任何构建产物/缓存可 clean 重建；不维护链接或副本（沿用既有硬约束）。

## 6. 阶段评审（§1.8②）
评审人：**用户**（唯一决策者）。评审输入：本阶段输出 + 判据记录 + 偏离说明（若有）。
评审清单（逐条回答）：① 是否达到准出判据？② 有无临时物残留？③ 有无未登记的偏离？④ 是否引入新 CLI/旁路（禁止）？⑤ 文档是否"取代而非叠加"？⑥ 是否可进入下一阶段？
**未通过 ⇒ 回退到本阶段起点**，不得"带病前进"。

## 7. 文档策略（§1.8⑤ + 自审查 P4/P7）
三类文档，**取代制**（新文档必须声明取代了谁）：
| 类 | 位置 | 内容 | 体量上限 |
|---|---|---|---|
| **规格** | `docs/development/` | 契约/规则/标准（唯一权威） | ≤ 16 KB/篇 |
| **计划** | `docs/plan/` | 阶段与批次计划（本文件） | ≤ 16 KB/篇 |
| **证据** | `docs/analysis/device-gates/` | 真机门禁记录 + 原始日志索引 | 索引 ≤ 8 KB；原始日志只索引不复制 |
- **分析类**仅保留"为何"（决策理由 + 沿革一句），≤ 8 KB/篇；被取代者移入 `docs/archive/`，不并存。
- **唯一入口**：每类一份索引（规格索引/计划索引/证据索引），其余文档必须由索引可达。

## 8. 小组与协作（§1.8⑥）
- 活跃 teammate **≤ 2**（一 writer + 一门禁）；其余保持 inactive 备用（可按需 resume）。
- 写范围**唯一**（同一文件同一时刻只有一个 writer）；构建**串行**（避免共享缓存撞车）。
- 子智能体只做被委派的事；Lead 负责评审、基线与最终交付。

## 9. 度量与改进（§1.8⑦）
每阶段复盘**一条**改进项并入库到规则文件（R# 新增或修订）。当前已入库的四条（来自本会话实践）：产物新鲜度闸门、一处读取、守卫必须能失败、原子写。

## 10. 风险与止损（§5.4）
| 风险 | 触发信号 | 止损动作 |
|---|---|---|
| 真机判据丢失/不可复现 | 设备异常（如 PM 破损态）、日志目录被清 | 立即转为 S6 运维项；**不回退架构结论** |
| 范围蔓延 | 一个批次出现第二个目标 | 砍范围，保阶段目标 |
| 环境噪声吞预算 | 构建/设备问题耗时超过功能改动 | 记录并挂 S6，**不在功能批里修** |
| 判据与实现纠缠 | 为了过门禁而改判据 | 禁止；改判据须走评审 |
| 文档再膨胀 | 新增分析类文档 | 走"取代"，否则不写 |

## 11. 跟踪与监督（§5.5）+ 策划文档管理（§5.6）
- 跟踪物：阶段状态（未开始/进行中/准出待评审/已评审）+ 批次记录（目标/写范围/判据/结果）。
- 本文件为**规划唯一入口**；阶段评审记录附于证据索引。修订本文件须注明沿革一句。
