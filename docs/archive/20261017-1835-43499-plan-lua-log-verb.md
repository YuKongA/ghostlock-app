# 计划：把日志暴露给 Lua（F 段 · L 级 · 2026-10-12）

> **2026-10-17 作废**：本文的载体（Lua 沙箱、script/wire 面、GLKv3 文档解析、pipeline/terminal 编排、nlohmann wire_doc）已从源码与构建中删除，
> 内容仅作历史记录；现行边界见 `docs/plan/MASTER-PLAN.md` §0.1。

## 0. 动机（用户裁定逐字）

> 「引入spdlog，开启异步，所有主要步骤执行前都要输出日志，**同时暴露给lua**」

⇒ 目的：编排在 Lua ✓（合「上层封装用 Lua」裁定 ✓）⇒ 脚本应能在**它自己的步骤前**打点 ✓，
而不是只能依赖 native 里写死的那些点 ✓。

## 1. 现状（本轮全量输出所得 ✓）

```
· `contract/op_registry.hpp:5` 逐字：「the script's visible face: a script reaches only the
  **seven names** …」⇒ **"七个"是既有不变量** ✗ ⇒ 加 `log` ⇒ 破它 ✗ ⇒ 故本变更 = **L 级** ✓
· surface 表在 `contract/script_surface.hpp` ✓（`kSurfacePhaseNames[]` `:128` ✓）
· `tests/surface_test.cpp` 有三个既有 pin ✓：`:60` 名唯一且非空 ✓ ；`:61` 无 `window.*` 行 ✓ ；
  `:62` 无 `run` 行（用户裁定删过 ✓）⇒ 新增行**同批**须过这三个 pin ＋ 行数 pin ✓
· 接缝已就绪 ✓（`support/log.hpp` 四个重载 ＋ `logging::open/close` ✓；⇒ 本次只是**把它接进 surface** ✓）
```

## 2. 两个选项（**须用户裁定** ✗）

```
① **把 `log` 作为第八个可见名** ✓（⇒ 直白 ✓；代价：**改"七个"这条不变量** ✗ 及其所有引用处 ✓）
② **复用既有动词承载** ✗：例如扩展 `cfg` 或 `settle` 的语义去顺带打点 ✗
    ⇒ **拒绝** ✗：那是"一个动词两件事" ✗ ⇒ 违背"一处权威"与"具名而非混用" ✓
③ （次选）**不暴露给 Lua** ✗，改为在 `procedures/*.lua` 里**约定**（⇒ 脚本无法自己打点 ✗）
⇒ ⇒ **⇒ 建议 ①** ✓：日志是**新的一类动作**（⇒ 不是既有动词的变体 ✓）⇒ 该有自己的名字 ✓；
   而"七个"这条不变量的**原意**是"脚本触不到内核操作之外的自由面" ✗ ⇒ 日志**不触内核** ✓ ⇒
   把它登记为第八名并**在 `op_registry.hpp` 注释里改写该句**（⇒ 说明为何第八名不破原意 ✓）✓
```

## 3. 设计（若采 ① ✓）

```
· surface 新行：`log` ✓ ；`phase = PreWindow` ✓（⇒ 与 `backend` 同相，**不新增内核行为** ✓）；
  `executable = true` ✓ ；`recordable = true` ✓
· 参数：`(handle, level, key)` ⇒ `arg_count = 3` ✓ ；两个串各有长度上界 ✓（⇒ 沿用既有 64 字节约定 ✓，
  超长 ⇒ **具名拒绝** ✗ 不截断 ✓）
· 语义：把 `(level, key)` 交给 `ghostlock::support::log` ✓（⇒ 与 native 打点**同一个入口** ✓）
· 拒绝：未知名 ⇒ 既有 `surface-unknown-name` ✓ ；参数越界 ⇒ 沿用既有量词拒绝码 ✓（⇒ 不新造码 ✓，合 L8 ✓）
· pin 同批更新：`surface_test.cpp` 的行数 pin ✗ ＋ 新断言（⇒ `log` 可达 ✓／越界具名拒绝 ✓）
```

## 7. 复审修订（design-critic v0.2 · 不通过 → 本节的整改 ✓）

### 7.1 **M1（阻断）证据完整性** —— 四件一起写进本计划 ✓

```
**问题（逐字 ✓）**：「脚本写出的行与 native 行**同文件、同格式、无来源标记** ⇒ ① 脚本可**伪造判据行**与
  「具名拒绝」行（含 `error` 级）；② 消息里的 `\n`/`\r`/控制字符可**注入整行** ⇒ ⇒ 使设计自己的
  **C3（一条 grep 定案）与 C5（与代码逐字相同）失去证据价值**」✓✓
**整改（四件 ✓）**：
  ① **来源标记**：Lua 行**必须**机器可辨 —— 在行首加 `[lua]`（或在 `what` 首键写 `src=lua` ✓）；
     且 **§4 的每一条判据 grep 一律只认 native 行** ✗（⇒ 判据定义里写明该过滤 ✓）
  ② **控制字符 ⇒ 具名拒绝** ✗：`\n`／`\r`／`\x1b` 一律**拒绝**（⇒ **不截断、不替换** ✗，与"超长即拒"同规 ✓）
     拒绝码沿用既有量词族 ✓（⇒ 不新造码 ✓ 合 L8 ✓）
  ③ **level 收敛**：脚本可用的 level 收敛为**声明子集** ✗（⇒ 建议仅 `debug`／`info` ⇒
     `warn`／`error` 保留给 native ✓ ⇒ 故**脚本无法伪造一条"具名拒绝"级**的行 ✓✓）
  ④ **可失败判据** ✓：构造一条 `[lua]` 伪造行（含 `error` 级）⇒ ⇒ **不得满足任何判据 grep** ✗
     （⇒ 且该实验**在副本**上做 ✗ ⇒ 不污染真树 ✓ —— 本会话已有此纪律 ✓）
```

### 7.2 **M4 相位与执行期语义** —— 采纳 critic 的建议 ✓

```
· `phase` 取 **`stage`** ✓（⇒ 理由：**调用发生在 stage** ✓；⇒ 与本计划的实现位置一致 ✓）
  ⇒ 若改取 `PreWindow` ⇒ 须给语义理由 ＋ 同步 phase 列的机器断言 ✗（⇒ 本计划**不**这么做 ✓）
· **stage-only 副作用语义** ✓：`log` 在执行期**不再产生新行** ✗ ⇒ staged 记录**不参与执行期** ✓
  ⇒ 判据（可失败 ✓）：一次 staged 执行后，日志中**同一 key 不得出现两次** ✓
```

### 7.3 **M10 参数形态** —— 采纳 ✓

```

· 若需带数 ⇒ **`(level, key, number)`** ✓ ⇒ 与 **M2** 的 `ArgSpec` 扩展**同批** ✓
```
