# 设计与规划审查原则（v0.2）

> 计划类（≤16 KiB = 16384 B）。**日期**：2026-10-07（v0.2 用户裁定）。
> **权威顺序**：`docs/development/软件工程守则.md`（最高思想）> `AGENTS.md` > `engineering-standards.md` / `design-philosophy.md` > 分析文档。
> **用途**：`design-critic` 岗位的审查依据 + 设计者自检清单。**自包含**：只引用本仓文件与规则编号（R 编号 = `engineering-rules.md`）。

## 1. 原则清单 v0.2

### A. 简并与去冗

- **A1 同一事实只写一处**：重复表述收拢为「一处 + 指针」。（R1）
- **A2 取代而非叠加**：新版本取代旧版本并划掉保留沿革，不得并列两套口径。（requirements Q10）
- **A3 体量配额**：规格/计划 ≤16 KiB、分析 ≤8 KiB、证据索引 ≤8 KiB（**8 KiB = 8192 B**）。（R30）
- **A4 一个概念一个名字**：同一结构出现两个名字即视同缺陷，必须合并或明示同源（`= 原名` + `static_assert`）。

### B. 单一权威与一处读取

- **B1 每事实一处权威**，其余为派生（生成或对拍保证）。（R1 / design-philosophy §3）
- **B2 一处读取**：任何数据只有一条读取路径；若并存 ⇒ 同批**逐值等价对拍**且声明仅作回退。（R2；本项由真实事故设立：载体/声明双读取路径曾使导出 `.bin` 静默丢队列）
- **B3 一处权威图**：一个结构只保留一处权威图，其它文档链接它，不重复画。（AGENTS 文档约定）

### C. 最小化与必要性

- **C1 最小改动**：只碰设计列出的文件；未列入改动清单的代码即冻结。（design-philosophy §5）
- **C2 可扩展性**：每个新结构必须写清**扩展点**——将来新增同类（op/backend/route/seam/执行器/脚本类型）时**改哪里、不改哪里**，并说明为何该结构易扩展。
- **C3 成本权衡（用户口径 2026-10-07）**：**编译期收益必须与工程成本权衡；当编译期/静态方案的工程成本超过更灵活方案时，让路**。禁止只写「更安全」「更符合原则」——必须给 CBN（§2）。
- **C4 不做无收益抽象**：抽象必须对应至少一处已存在的复用或已登记的扩展点。
- **C5 临时物零容忍**：临时开关/旁路同批登记并同批移除。（守则 §6.2；R13）

### D. 可验证性（**D1 为准**）

- **D1 判据形式 = 黑盒/白盒 + 极端输入值**（**取代** AGENTS「守卫/断言必须证明能失败」与 `engineering-rules.md` **R10**）：
  - **黑盒**：外部可观测行为（命令行退出码/输出、wire 文档字节、日志行、标记文件）；
  - **白盒**：内部结构（单元测试、`static_assert`、编译期表断言、层表/账本）；
  - **只列极端输入值下的预期结果**：边界（0/1/MAX）、空、超限、非法组合、越界数值；
  - **「绝对不可能发生」的用例不测**（不得为不可达分支造用例）；
  - **不再要求**为守卫/断言做**造错（证伪）实验**——该要求自 v0.2 起为**可选手段**而非门槛。
- **D2 判据分层**：离线可重复 / native 构建 / 真机，各有一处入口与记录。（R14）
- **D3 真机是功能的唯一判据**；离线相似物仅作诊断。（R15）
- **D4 产物身份 + 新鲜度**：报告含路径/字节/mtime/sha；观测与代码矛盾时先核产物新鲜度。（R16）
- **D5 失败数读 XML 全量**，不看控制台尾部；报告给三桶计数。（R17）
- **D6 具名诊断是契约**：阶段/原因标识发布后不得改义。（R11）
- **D7 fail-closed**：失败不得降级继续（无默认继续/自动换路/自动重试）。（R12）

### E. 结构约束与安全

- **E1 层间只传数据**；禁公共/控制/内容耦合。（R3）
- **E2 功能内聚**：模块职责可一句话说清且不可再分。（R4）
- **E3 编译期锁定**：组合→步骤集→终端在编译期绑定，运行期只做声明符合性检查。（R6）
- **E4 PI 窗口内禁间接分派/分配/首次触碰新页**：窗口外允许虚接口（gate/计划/配置构造/终端交接）。（ADR-0001:183、ADR-0004:188-189、`route_lifecycle.hpp:9-11`）
- **E5 双读取路径 = 高危形态**：同一数据的第二条读取路径必须同批补跨路径等价对拍并声明回退关系。（R2；本仓 M5 事故）
- **E7 共享工作树保护（硬规则，2026-10-07 事故后立）**：任何 teammate **不得**执行会改变共享工作树的 git 命令（`checkout/restore/stash/reset/clean`），**也不得**等效写回（`git show REV:path > path`）；历史比较只用只读形式（`git show REV:path` 不重定向、`git diff REV -- path`、`git log`）。
- **E8 写回完整性（硬规则，同源）**：**禁止分片读 + 全文写回**——`read(offset/limit)` 只给窗口、`write` 整体替换；读须整份读（或确认读到 `totalLines`）或改用定点 `edit`。若确需整份写回，**写回前后核对字节数与行数**并在报告给出。
- **E6 守卫可失败**：**v0.2 起由 D1 取代**；仍可作为**可选**加强手段（尤其是 vacuous 断言风险场景）。

### F. 记录与沿革

- **F1 不删历史**：被推翻的提法划掉保留 + 一行理由；用户裁决必须记录。（AGENTS 沿革条款）
- **F2 技术债预判（v0.2 扩展）**：每个新组件/功能/结构必须列「**未来可能新增的功能** + **预估技术债** + **偿还时机**」，并登记到 decisions（或专门的技术债文件）。
- **F3 强制确认须核沿革与技术债**：用户强制越权时，审查者必须核对「沿革记录 + 技术债登记」是否都在；缺一即视为未完成。
- **F4 决策可检索**：时间 · 原则版本 · 总判 · 阻断数，一行一条。（design-philosophy §9）

### G. 事实与证据

- **G1 每条结论带依据**：`file:line` 或原则/R 编号；不得只有形容词。
- **G2 禁止外部计划引用与未定义标签**：标签必须能在本族文档中找到定义（否则先补「标签 → 来源」表）。
- **G3 未核实项显式标注**：不得把推测写成事实（写「未核实」并给核实路径）。
- **G4 审查前提 = 冻结快照**：记录 HEAD/文档哈希/时间；期间有写入则声明「不覆盖」，冻结后复跑。

## 2. CBN（成本权衡依据）规范

**适用**：任何「编译期 vs 运行期」「静态策略 vs 虚接口/动态」「合并 vs 拆分」「新增结构 vs 复用既有」的选择。**禁止只写「更安全」**。

| 字段 | 必填内容 |
|---|---|
| **决策点** | 一句话：在哪个结构/哪一层做选择 |
| **备选（≥2）** | 至少含一个**更灵活**方案（运行期/动态/拆分） |
| **收益** | **可度量**（字节数、分支数、扩展触点、评审/门禁成本…至少一个数字） |
| **成本** | 工程量 + **每次扩展的边际成本**（例：每新增一个 op 需改几处） |
| **翻转条件** | 什么情况下**必须改选**另一方案（可判定，不写「视情况」） |
| **结论** | 选定方案 + 一句为何 |

- **决策规则**：若「更灵活方案」的**总成本（含边际）更低**而收益差距不可度量 ⇒ **选更灵活方案**（C3 用户口径）。
- **刻度**：收益列缺数字 = 不合格；成本列缺边际成本 = 不合格；备选 <2 = 不合格。

## 3. 审查产出格式（design-critic 固定格式）

| 编号 | 严重度 | 位置 | 问题 | 必须怎么改 | 依据 |
|---|---|---|---|---|---|
| C1 | 阻断/重要/建议 | `file:line` 或 文档+节 | 一句话 | 可执行的修法 | 守则条 / R 编号 / `file:line` |

- **总判（末尾一行）**：`可进批准 gate` 或 `仍需修订（列必改项）`。
- **总判口径**：**阻断项未关闭 ⇒ 不得进批准 gate**；重要项可挂待办并写明偿还时机；建议项不阻塞。
- **必附**：`验证了什么 / 没验证什么`（各一段，逐条可核）。

## 4. 沿革与版本

- **v0.1**（2026-10-07 早）：判据含「造错必失败 / 证伪实验」**通用要求**（承 AGENTS 验证门槛 + `engineering-rules.md` R10）。
- **v0.2**（2026-10-07 用户裁定）：
  1. **D1 为准**：判据改为**黑盒/白盒 + 极端输入值**；**删除证伪实验的通用要求**（AGENTS 同条与 R10 保留原文、标注为**可选手段**）；「不可能发生」的用例不测。
  2. **C3 新增用户口径**：编译期收益须与工程成本权衡；成本超过更灵活方案 ⇒ **让路**。
  3. **F2 扩展为技术债预判**（未来功能 + 预估债 + 偿还时机）。
  4. **登记越权与技术债**：越过 AGENTS「守卫必须能失败」经验条目（用户 2026-10-07 确认）；代价 = **vacuous 断言风险回归**；偿还 = 由**黑盒/白盒 + 极端值用例**覆盖替代，见 decisions 的取代记录。
